Module 1. Mathematical analysis of nonrecursive algorithms

A nonrecursive algorithm is built from loops. To analyze it, we write the number of basic operations as a sum and then simplify that sum.

Goals of the module

By the end of this module you will be able to:

  1. apply the five-step plan to any algorithm made of loops;
  2. turn nested loops into sums, including loops whose bounds depend on the outer variable;
  3. simplify sums using standard rules and formulas and find the order of growth;
  4. analyze the worst, best and average case separately when they differ;
  5. recognize the six typical mistakes;
  6. check a derived formula by counting operations in a Python program.

Time needed: about 2–3 hours, plus 2 hours for the tasks.

1. The general plan of analysis

Every analysis in this module follows the same five steps (Levitin, Section 2.3).

  1. Choose the input size parameter. Decide which number describes how big the input is (usually \(n\), the number of elements).
    Why: the answer will be a function of this parameter.
  2. Identify the basic operation. As a rule, it is the operation in the innermost loop.
    Why: it is executed most often, so it determines the order of growth.
  3. Check whether the count depends only on the size. If it also depends on the particular input (for example, the loop can stop early), analyze the worst, best and, if needed, average case separately.
    Why: otherwise "the number of operations for size \(n\)" is not a single number.
  4. Set up a sum that expresses how many times the basic operation is executed. Each loop becomes one \(\sum\) sign, with the same bounds as the loop.
  5. Simplify the sum with standard formulas and rules to get a closed-form formula, or at least the order of growth.
Typical mistakes at each step
  • Step 1: using the value of a number instead of its size (number of bits).
  • Step 2: choosing an operation outside the innermost loop, such as an assignment executed once.
  • Step 3: forgetting about an early return and presenting the worst case as "the" answer.
  • Step 4: wrong bounds in the sum (off-by-one).
  • Step 5: algebra mistakes; dropping a term that is not of lower order.
More details are in the section Typical mistakes.

2. Summation tools

The notation \(\displaystyle\sum_{i=l}^{u} a_i\) means \(a_l + a_{l+1} + \dots + a_u\). The variable \(i\) is the index, \(l\) and \(u\) are the lower and upper bounds.

Rules for manipulating sums

\[ \text{(R1)}\quad \sum_{i=l}^{u} c\,a_i = c \sum_{i=l}^{u} a_i \qquad\qquad \text{(R2)}\quad \sum_{i=l}^{u} (a_i \pm b_i) = \sum_{i=l}^{u} a_i \pm \sum_{i=l}^{u} b_i \] \[ \text{(R3)}\quad \sum_{i=l}^{u} a_i = \sum_{i=l}^{m} a_i + \sum_{i=m+1}^{u} a_i \quad (l \le m < u) \]

(R1): a constant factor can be taken outside the sum. (R2): a sum of a sum is split into two sums. (R3): a sum can be split into two parts.

Counting the number of terms

\[ \text{(S1)}\quad \sum_{i=l}^{u} 1 = u - l + 1 \qquad (l \le u) \]
Remember the "+1"

From 3 to 7 there are \(7 - 3 + 1 = 5\) numbers: 3, 4, 5, 6, 7. From \(0\) to \(n-1\) there are \(n\) numbers. From \(i+1\) to \(n-1\) there are \(n-1-i\) numbers.

Standard formulas

\[ \text{(S2)}\quad \sum_{i=1}^{n} i = 1 + 2 + \dots + n = \frac{n(n+1)}{2} \approx \frac{1}{2}n^2 \in \Theta(n^2) \] \[ \text{(S3)}\quad \sum_{i=1}^{n} i^2 = 1^2 + 2^2 + \dots + n^2 = \frac{n(n+1)(2n+1)}{6} \approx \frac{1}{3}n^3 \in \Theta(n^3) \] \[ \text{(S4)}\quad \sum_{i=0}^{n} a^i = 1 + a + \dots + a^n = \frac{a^{n+1} - 1}{a - 1} \quad (a \ne 1), \qquad \text{in particular} \quad \sum_{i=0}^{n} 2^i = 2^{n+1} - 1 \] \[ \text{(S5)}\quad \sum_{i=1}^{n} i^k = 1^k + 2^k + \dots + n^k \approx \frac{n^{k+1}}{k+1} \in \Theta(n^{k+1}) \]

(S5) is the general pattern: summing \(i^k\) "adds one to the exponent". It is useful when we only need the order of growth.

Mini-example: using the rules together \[ \sum_{i=1}^{n} (2i + 3) \overset{R2}{=} \sum_{i=1}^{n} 2i + \sum_{i=1}^{n} 3 \overset{R1}{=} 2\sum_{i=1}^{n} i + 3\sum_{i=1}^{n} 1 \overset{S2,S1}{=} 2\cdot\frac{n(n+1)}{2} + 3n = n^2 + 4n. \]

Check for \(n = 2\): \((2+3) + (4+3) = 12\) and \(2^2 + 4\cdot2 = 12\). ✔

3. Worked examples

Each example is solved with the five steps of the plan. Read the pseudocode first and try to guess the answer before reading the analysis.

Example 1.1. MaxElement — the largest element of an array

ALGORITHM MaxElement(A[0..n − 1])
//Determines the value of the largest element in a given array
//Input: An array A[0..n − 1] of real numbers
//Output: The value of the largest element in A
maxval ← A[0]
for i ← 1 to n − 1 do
    if A[i] > maxval
        maxval ← A[i]
return maxval

1. Input size: the number of elements \(n\).

2. Basic operation: the comparison \(A[i] > maxval\). It is inside the loop and is executed on every iteration. (The assignment \(maxval \leftarrow A[i]\) is not a good choice: how often it runs depends on the data.)

3. Cases: the loop always runs from 1 to \(n-1\) and never stops early, so there is only one case.

4. Sum: one comparison per value of \(i\) from 1 to \(n-1\): \[ C(n) = \sum_{i=1}^{n-1} 1. \]

5. Solve: by (S1), \(C(n) = (n-1) - 1 + 1 = n - 1 \in \Theta(n).\)

Example 1.2. UniqueElements — are all elements distinct?

ALGORITHM UniqueElements(A[0..n − 1])
//Determines whether all the elements in a given array are distinct
//Output: Returns "true" if all the elements in A are distinct and "false" otherwise
for i ← 0 to n − 2 do
    for j ← i + 1 to n − 1 do
        if A[i] = A[j] return false
return true

1. Input size: \(n\).

2. Basic operation: the comparison \(A[i] = A[j]\) in the innermost loop.

3. Cases: the algorithm can stop early (return false), so the count depends on the input. We analyze the worst and the best case.

  • Worst case: the loops run completely. This happens when all elements are distinct, or when the only equal pair is the last pair compared.
  • Best case: \(A[0] = A[1]\). The first comparison already returns false: \(C_{best}(n) = 1\).

4. Sum (worst case): for fixed \(i\), \(j\) goes from \(i+1\) to \(n-1\): \[ C_{worst}(n) = \sum_{i=0}^{n-2} \sum_{j=i+1}^{n-1} 1. \]

5. Solve: the inner sum has \((n-1)-(i+1)+1 = n-1-i\) terms, so \[ C_{worst}(n) = \sum_{i=0}^{n-2} (n-1-i) = (n-1) + (n-2) + \dots + 1 = \frac{(n-1)n}{2} \approx \frac12 n^2 \in \Theta(n^2). \]

So \(C_{worst}(n) \in \Theta(n^2)\) and \(C_{best}(n) \in \Theta(1)\). In general, the algorithm is in \(O(n^2)\).

Example 1.3. MatrixMultiplication — product of two \(n \times n\) matrices

ALGORITHM MatrixMultiplication(A[0..n − 1, 0..n − 1], B[0..n − 1, 0..n − 1])
//Multiplies two square matrices of order n by the definition-based algorithm
//Output: Matrix C = AB
for i ← 0 to n − 1 do
    for j ← 0 to n − 1 do
        C[i, j] ← 0.0
        for k ← 0 to n − 1 do
            C[i, j] ← C[i, j] + A[i, k] ∗ B[k, j]
return C

1. Input size: the order of the matrices \(n\).

2. Basic operation: multiplication \(A[i,k] * B[k,j]\) in the innermost loop. (Additions happen exactly as often, so choosing addition gives the same count.)

3. Cases: no early exit — one case.

4. Sum: three loops give three sums: \[ M(n) = \sum_{i=0}^{n-1} \sum_{j=0}^{n-1} \sum_{k=0}^{n-1} 1. \]

5. Solve: work from the inside out. The innermost sum is \(n\), the middle is \(n \cdot n\), the outer is \(n \cdot n^2\): \[ M(n) = \sum_{i=0}^{n-1} \sum_{j=0}^{n-1} n = \sum_{i=0}^{n-1} n^2 = n^3 \in \Theta(n^3). \]

Running time: \(T(n) \approx c_m M(n) + c_a A(n) = (c_m + c_a)\,n^3\), where \(c_m\) and \(c_a\) are the times of one multiplication and one addition.

Example 1.4. A loop with a dependent bound

sum ← 0
for i ← 1 to n do
    for j ← 1 to i do
        sum ← sum + i ∗ j
return sum

1. Input size: \(n\). 2. Basic operation: the multiplication \(i * j\). 3. Cases: one case.

4. Sum: the inner loop bound is \(i\), which depends on the outer variable. For \(i = 1\) the inner loop runs once, for \(i = 2\) twice, …, for \(i = n\) it runs \(n\) times: \[ C(n) = \sum_{i=1}^{n} \sum_{j=1}^{i} 1 = \sum_{i=1}^{n} i. \]

5. Solve: by (S2), \(C(n) = \dfrac{n(n+1)}{2} \in \Theta(n^2).\)

Picture to remember

A dependent bound like \(j \le i\) "cuts the square in half". The order of growth is still \(n^2\); only the constant changes from 1 to \(\tfrac12\).

Example 1.5. A multiplicative loop — number of binary digits

ALGORITHM Binary(n)
//Input: A positive decimal integer n
//Output: The number of binary digits in n's binary representation
count ← 1
while n > 1 do
    count ← count + 1
    n ← ⌊n/2⌋
return count

1. Input size: the number \(n\) itself (we count how many times the loop runs as a function of \(n\)).

2. Basic operation: the comparison \(n > 1\) that controls the loop.

3. Cases: one case for each \(n\).

4. Count: here the loop variable is divided by 2 each time, not increased by 1, so we cannot just write \(\sum 1\) from 1 to \(n\). Follow the value of \(n\):

After \(t\) iterations the value is about \(n / 2^t\). The loop stops when it reaches 1, i.e. after \(\lfloor \log_2 n \rfloor\) iterations. The comparison is made once more at the end (when it is false).

5. Result: \(C(n) = \lfloor \log_2 n \rfloor + 1 \in \Theta(\log n).\)

Rule

If a loop variable is multiplied or divided by a constant \(b > 1\) on every iteration, the loop runs \(\Theta(\log_b n) = \Theta(\log n)\) times.

Example 1.6. SelectionSort Original

Selection sort finds the smallest element of the unsorted part and swaps it to the front.

ALGORITHM SelectionSort(A[0..n − 1])
//Sorts a given array by selection sort
//Output: Array A[0..n − 1] sorted in nondecreasing order
for i ← 0 to n − 2 do
    min ← i
    for j ← i + 1 to n − 1 do
        if A[j] < A[min]  min ← j
    swap A[i] and A[min]

1. Input size: \(n\).

2. Basic operation: the key comparison \(A[j] < A[min]\).

3. Cases: there is no early exit; both loops always run completely. The number of comparisons is the same for every input of size \(n\), even an already sorted array.

4. Sum: \[ C(n) = \sum_{i=0}^{n-2} \sum_{j=i+1}^{n-1} 1 = \sum_{i=0}^{n-2} (n-1-i). \]

5. Solve: substitute \(k = n-1-i\); when \(i\) goes from 0 to \(n-2\), \(k\) goes from \(n-1\) down to 1: \[ C(n) = \sum_{k=1}^{n-1} k = \frac{(n-1)n}{2} \in \Theta(n^2). \]

Bonus: the number of swaps is \(n - 1\) (one per outer iteration), which is only \(\Theta(n)\). That is why selection sort is used when swapping is expensive.

Check for \(n = 4\): \(i=0\): 3 comparisons, \(i=1\): 2, \(i=2\): 1. Total 6, and \(4\cdot3/2 = 6\). ✔

Example 1.7. PrefixAverages — a hidden quadratic cost Original

For every position \(i\), compute the average of the first \(i+1\) elements: \(P[i] = (A[0] + \dots + A[i]) / (i+1)\).

ALGORITHM PrefixAverages(A[0..n − 1])
//Output: Array P[0..n − 1], P[i] is the average of A[0..i]
for i ← 0 to n − 1 do
    s ← 0
    for j ← 0 to i do
        s ← s + A[j]
    P[i] ← s / (i + 1)
return P

1. Input size: \(n\).

2. Basic operation: the addition \(s + A[j]\) (innermost loop). The division is outside the inner loop and runs only \(n\) times.

3. Cases: one case.

4. Sum: the inner loop runs for \(j = 0, \dots, i\), that is \(i+1\) times: \[ A(n) = \sum_{i=0}^{n-1} \sum_{j=0}^{i} 1 = \sum_{i=0}^{n-1} (i+1). \]

5. Solve: substitute \(k = i+1\), so \(k\) goes from 1 to \(n\): \[ A(n) = \sum_{k=1}^{n} k = \frac{n(n+1)}{2} \in \Theta(n^2). \]

Lesson: analysis helps you improve the algorithm

The inner loop recomputes the same partial sum again and again. If we keep a running sum (s ← s + A[i] once per \(i\), with s ← 0 before the loop), we need only \(n\) additions: \(\Theta(n)\) instead of \(\Theta(n^2)\).

5. Average case: sequential search

ALGORITHM SequentialSearch(A[0..n − 1], K)
//Searches for a given value in a given array by sequential search
//Output: The index of the first element in A that matches K or −1 if there are no matching elements
i ← 0
while i < n and A[i] ≠ K do
    i ← i + 1
if i < n return i
else return −1

Basic operation: the key comparison \(A[i] \ne K\). Worst case \(C_{worst}(n) = n\), best case \(C_{best}(n) = 1\). What happens "on average"?

Assumptions
  1. The probability that the search is successful (the key is in the array) is \(p\), where \(0 \le p \le 1\).
  2. In a successful search, the first match is equally likely to be at any of the \(n\) positions: probability \(p/n\) for each position.

If the first match is at position \(i\) (counting from 1), the algorithm makes exactly \(i\) comparisons. If the search is unsuccessful (probability \(1 - p\)), it makes \(n\) comparisons. The average is the expected value: the sum of (number of comparisons) × (probability).

\[ C_{avg}(n) = \Big[ 1\cdot\frac{p}{n} + 2\cdot\frac{p}{n} + \dots + n\cdot\frac{p}{n} \Big] + n\cdot(1-p) = \frac{p}{n}\sum_{i=1}^{n} i + n(1-p) = \frac{p}{n}\cdot\frac{n(n+1)}{2} + n(1-p). \] \[ \boxed{\,C_{avg}(n) = \frac{p(n+1)}{2} + n(1-p)\,} \]
\(p\)meaning\(C_{avg}(n)\)
1the key is always present\(\frac{n+1}{2}\): about half of the array is checked
0the key is never present\(n\): the whole array is checked
1/2present half of the time\(\frac{n+1}{4} + \frac{n}{2} = \frac{3n+1}{4}\)

In every case \(C_{avg}(n) \in \Theta(n)\).

The average case is not "(best + worst) / 2"

Here \((1 + n)/2\) happens to equal \(C_{avg}\) for \(p = 1\), but this is a coincidence. The average case always needs a probability model of the inputs.

6. Typical mistakes

MistakeExampleHow to avoid it
Wrong basic operation In MaxElement, counting the assignment maxval ← A[i]. It runs 0 times on a decreasing array and \(n-1\) times on an increasing one, which looks like "cases" that do not really exist. Take the operation that is executed on every iteration of the innermost loop.
Size vs. value Trial-division primality test makes about \(\sqrt n\) divisions. "\(\sqrt n\) is sublinear, so the algorithm is fast" — wrong: the size is \(b \approx \log_2 n\) bits, and \(\sqrt n \approx 2^{b/2}\) is exponential in \(b\). For algorithms on a single number, measure the size in bits.
Mixing up cases "UniqueElements is \(\Theta(n^2)\)". Only the worst case is; the best case is \(\Theta(1)\). When there is an early exit, always say which case you mean. Use \(O\) for a statement about all inputs.
Off-by-one errors Writing \(n - i\) instead of \(n - 1 - i\) for the number of values of \(j\) from \(i+1\) to \(n-1\). Use \(u - l + 1\) and check with a small \(n\) by hand.
Ignoring an early exit Writing \(\sum_{i=0}^{n-1} 1 = n\) for sequential search as if it always scans the whole array. Look for return, break or a compound loop condition.
Hidden cost A single line like if K in A or B ← copy of A hides a loop of \(n\) operations. So does calling another algorithm inside a loop. Expand every built-in operation into the loop it really performs before counting.

7. Empirical verification

A formula derived on paper can contain a mistake. A quick way to check it is to count the operations in a real program and compare.

  1. Implement the algorithm in Python exactly as in the pseudocode.
  2. Add a counter variable and increase it by 1 right next to the basic operation.
  3. Run the program for several sizes \(n\) (for example 10, 100, 1000) and for the inputs of the case you analyzed (worst, best, random).
  4. Compare the counter with the formula. For an exact formula the numbers must be equal. For an order of growth, the ratio \(C(n)/g(n)\) should approach a constant.
def unique_elements(a):
    count = 0                       # operation counter
    n = len(a)
    for i in range(n - 1):          # i = 0 .. n-2
        for j in range(i + 1, n):   # j = i+1 .. n-1
            count += 1              # one comparison A[i] = A[j]
            if a[i] == a[j]:
                return False, count
    return True, count

for n in [10, 100, 1000]:
    _, c = unique_elements(list(range(n)))   # distinct elements = worst case
    print(n, c, n * (n - 1) // 2, c / n**2)

Output: the second and third columns are equal (45, 4950, 499500), and the last column approaches 0.5 — the constant \(\tfrac12\) in \(\tfrac12 n^2\).

8. Summary and formula cheat sheet

Summary
  • Plan: size → basic operation → cases? → sum → simplify.
  • Each loop becomes one \(\sum\) with the same bounds. Nested loops become nested sums; simplify from the inside out.
  • Independent loops multiply (\(n \cdot n \cdot n = n^3\)); a dependent bound \(j \le i\) gives \(\sum i \approx n^2/2\).
  • A variable that is multiplied or divided by a constant gives \(\Theta(\log n)\) iterations.
  • With an early exit, analyze the worst, best and average case separately. The average case needs a probability model.
  • Always check the result on a small \(n\) by hand, or with an operation counter.
