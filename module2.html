Module 2. Mathematical analysis of recursive algorithms

A recursive algorithm calls itself on a smaller input. Its number of operations is therefore described by an equation that refers to itself — a recurrence relation. In this module we learn to set up and solve such equations.

Goals of the module

By the end of this module you will be able to:

  1. apply the five-step plan to a recursive algorithm;
  2. write a recurrence relation together with its initial condition;
  3. solve a recurrence by backward substitution and check the result by induction;
  4. draw a recursion tree and use it to count operations;
  5. explain why the naive recursive Fibonacci algorithm is exponential and how to fix it;
  6. estimate the memory used by recursion (stack depth) and recognize tail recursion.

Prerequisite: summation formulas from Module 1, especially the geometric series. Time needed: about 2–3 hours plus 2 hours for the tasks.

1. The general plan of analysis

The plan is almost the same as in Module 1 (Levitin, Section 2.4). Only step 4 changes: instead of a sum we write a recurrence relation.

  1. Choose the input size parameter \(n\).
  2. Identify the basic operation.
  3. Check whether the count depends only on \(n\). If not, analyze the worst, best and average cases separately.
  4. Set up a recurrence relation, with an appropriate initial condition, for the number of times the basic operation is executed.
  5. Solve the recurrence, or at least find the order of growth of its solution.
Definitions

A recurrence relation (recurrence) is an equation that expresses \(x(n)\) through the values of \(x\) at smaller arguments, for example \(x(n) = x(n-1) + 1\).

An initial condition gives the value of \(x\) at the smallest argument, for example \(x(0) = 0\). Without it the recurrence has infinitely many solutions.

To solve a recurrence means to find an explicit formula for \(x(n)\) that does not refer to other values of \(x\).

How to write the recurrence: a recipe

Look at one call of the algorithm on input \(n\) and ask:

  1. How many recursive calls does it make, and on which sizes? Each call contributes \(C(\text{its size})\).
  2. How many basic operations does it do itself, outside the recursive calls? Add this number.
  3. What happens in the base case (the case without recursion)? This gives the initial condition.

2. The method of backward substitutions

The idea: replace \(x(n-1)\) using the same recurrence, then \(x(n-2)\), and so on, until a pattern appears. Then jump directly to the initial condition.

  1. Write the recurrence for \(n\).
  2. Substitute the recurrence for the smaller argument (\(n-1\) or \(n/2\)) into it. Simplify.
  3. Repeat 2–3 times and guess the general form after \(i\) substitutions.
  4. Choose \(i\) so that the argument becomes the initial value (e.g. \(n - i = 0\)).
  5. Substitute the initial condition and simplify to a closed form.
  6. Verify the result: by mathematical induction, or at least by checking a few small values of \(n\).
Why do we need step 6?

Step 3 is a guess ("…and so on"). It is usually right, but to be sure we prove it. A proof by mathematical induction has two parts:

  • Base: the formula is correct for the initial value of \(n\).
  • Inductive step: if the formula is correct for \(n - 1\), then it is correct for \(n\) (use the recurrence).

3. Worked examples

Example 2.1. Factorial \(n!\)

ALGORITHM F(n)
//Computes n! recursively
//Input: A nonnegative integer n
//Output: The value of n!
if n = 0 return 1
else return F(n − 1) ∗ n

1. Input size: \(n\). (Strictly speaking, the size is the number of bits; here we follow Levitin and count as a function of \(n\).)

2. Basic operation: the multiplication \(F(n-1) * n\).

3. Cases: one case.

4. Recurrence: to compute \(F(n)\) for \(n > 0\), the algorithm makes \(M(n-1)\) multiplications inside the call \(F(n-1)\) and one more multiplication itself. For \(n = 0\) it makes none: \[ M(n) = M(n-1) + 1 \quad \text{for } n > 0, \qquad M(0) = 0. \]

5. Solve by backward substitution: \[ \begin{aligned} M(n) &= M(n-1) + 1 \\ &= [M(n-2) + 1] + 1 = M(n-2) + 2 \\ &= [M(n-3) + 1] + 2 = M(n-3) + 3 \\ &\;\;\vdots \\ &= M(n-i) + i. \end{aligned} \] Take \(i = n\): \(M(n) = M(0) + n = n\).

Verify by induction. Base: \(M(0) = 0\). ✔ Step: if \(M(n-1) = n - 1\), then \(M(n) = (n-1) + 1 = n\). ✔

Answer: \(M(n) = n \in \Theta(n)\).

Example 2.2. Tower of Hanoi

There are \(n\) disks of different sizes on peg 1, the largest at the bottom. Move them all to peg 3, one disk at a time, never putting a larger disk on a smaller one. Peg 2 is auxiliary.

ALGORITHM Hanoi(n, from, to, aux)
//Moves n disks from peg "from" to peg "to" using peg "aux"
if n = 1
    move the disk from from to to
else
    Hanoi(n − 1, from, aux, to)      //move n − 1 disks out of the way
    move disk n from from to to
    Hanoi(n − 1, aux, to, from)      //put them back on top

1. Input size: the number of disks \(n\). 2. Basic operation: moving one disk. 3. Cases: one case.

4. Recurrence: two recursive calls on \(n-1\) disks plus one move: \[ M(n) = 2M(n-1) + 1 \quad \text{for } n > 1, \qquad M(1) = 1. \]

5. Solve: \[ \begin{aligned} M(n) &= 2M(n-1) + 1 \\ &= 2[2M(n-2) + 1] + 1 = 2^2 M(n-2) + 2 + 1 \\ &= 2^2[2M(n-3) + 1] + 2 + 1 = 2^3 M(n-3) + 2^2 + 2 + 1 \\ &\;\;\vdots \\ &= 2^i M(n-i) + 2^{i-1} + \dots + 2 + 1 = 2^i M(n-i) + 2^i - 1. \end{aligned} \] The initial condition is at \(n = 1\), so take \(i = n - 1\): \[ M(n) = 2^{n-1} M(1) + 2^{n-1} - 1 = 2^{n-1} + 2^{n-1} - 1 = 2^n - 1 \in \Theta(2^n). \]

Verify by induction. Base: \(M(1) = 2^1 - 1 = 1\). ✔ Step: if \(M(n-1) = 2^{n-1} - 1\), then \(M(n) = 2(2^{n-1} - 1) + 1 = 2^n - 1\). ✔

Recursion tree. Draw each call as a node with its value of \(n\); its children are the calls it makes.

The tree gives the same answer without algebra: count the nodes level by level and use the geometric series.

How big is \(2^n - 1\)?

For 64 disks: \(2^{64} - 1 \approx 1.8\cdot10^{19}\) moves. At one move per second that is about 585 billion years. The algorithm is optimal — no algorithm can solve the puzzle with fewer moves — the problem itself is exponential.

Example 2.3. Counting binary digits recursively

ALGORITHM BinRec(n)
//Input: A positive decimal integer n
//Output: The number of binary digits in n's binary representation
if n = 1 return 1
else return BinRec(⌊n/2⌋) + 1

1. Input size: \(n\). 2. Basic operation: the addition \(+1\). 3. Cases: one case.

4. Recurrence: one recursive call on \(\lfloor n/2 \rfloor\) plus one addition: \[ A(n) = A(\lfloor n/2 \rfloor) + 1 \quad \text{for } n > 1, \qquad A(1) = 0. \]

5. Solve. The floor makes backward substitution hard. We use the standard trick: solve only for \(n = 2^k\), where \(\lfloor n/2 \rfloor = 2^{k-1}\) exactly: \[ \begin{aligned} A(2^k) &= A(2^{k-1}) + 1 \\ &= [A(2^{k-2}) + 1] + 1 = A(2^{k-2}) + 2 \\ &\;\;\vdots \\ &= A(2^{k-i}) + i = A(2^0) + k = k. \end{aligned} \] Since \(k = \log_2 n\): \(A(n) = \log_2 n \in \Theta(\log n)\) for \(n = 2^k\).

For all \(n\) the exact solution is \(A(n) = \lfloor \log_2 n \rfloor\). By the smoothness rule (Levitin, Appendix B), the order of growth found for powers of 2 is valid for all \(n\), because \(A(n)\) is non-decreasing and \(\log n\) is a "smooth" function.

4. Two more examples Original

Example 2.4. Recursive maximum search Original

ALGORITHM RecMax(A[0..n − 1])
//Returns the largest element of A, n ≥ 1
if n = 1 return A[0]
m ← RecMax(A[0..n − 2])
if A[n − 1] > m return A[n − 1]
else return m

1. Input size: the number of elements \(n\).

2. Basic operation: the comparison \(A[n-1] > m\).

3. Cases: no early exit depends on the data — one case.

4. Recurrence: one recursive call on \(n - 1\) elements plus one comparison. The base case (one element) makes no comparison: \[ C(n) = C(n-1) + 1 \quad \text{for } n > 1, \qquad C(1) = 0. \]

5. Solve: \( C(n) = C(n-1) + 1 = C(n-2) + 2 = \dots = C(n-i) + i. \) Take \(i = n - 1\): \(C(n) = C(1) + n - 1 = n - 1 \in \Theta(n)\).

Verify. Base: \(C(1) = 1 - 1 = 0\). ✔ Step: \(C(n) = (n - 2) + 1 = n - 1\). ✔

Comparison with MaxElement (Module 1, Example 1.1): the same \(n - 1\) comparisons. But RecMax also uses a stack of depth \(n\), so it needs \(\Theta(n)\) extra memory, while the loop needs \(\Theta(1)\).

Careful with the initial condition

If you write \(C(1) = 1\) (as if the base case made a comparison), you get \(C(n) = n\) — wrong by one. Always read the base case of the pseudocode to see how many basic operations it really performs.

Example 2.5. Fast exponentiation \(a^n\) Original

Idea: \(a^{n} = (a^{n/2})^2\) if \(n\) is even, and \(a^{n} = (a^{\lfloor n/2\rfloor})^2 \cdot a\) if \(n\) is odd.

ALGORITHM Power(a, n)
//Computes an for a real a and an integer n ≥ 0
if n = 0 return 1
t ← Power(a, ⌊n/2⌋)
if n mod 2 = 0 return t ∗ t
else return t ∗ t ∗ a

1. Input size: the exponent \(n\).

2. Basic operation: multiplication.

3. Cases: an even \(n\) costs 1 multiplication in the current call, an odd \(n\) costs 2. So the count depends on the binary digits of \(n\), not only on its magnitude. We first solve for \(n = 2^k\).

4. Recurrence: \[ M(n) = \begin{cases} M(\lfloor n/2\rfloor) + 1, & n \text{ even}, n > 0,\\ M(\lfloor n/2\rfloor) + 2, & n \text{ odd}, \end{cases} \qquad M(0) = 0. \] In particular \(M(1) = M(0) + 2 = 2\).

5. Solve for \(n = 2^k\). All of \(2^k, 2^{k-1}, \dots, 2\) are even, so \[ M(2^k) = M(2^{k-1}) + 1 = M(2^{k-2}) + 2 = \dots = M(2^{k-i}) + i = M(1) + k = k + 2. \] So \(M(n) = \log_2 n + 2\) for \(n = 2^k\).

For any \(n \ge 1\) one can show \(\lfloor \log_2 n\rfloor + 2 \le M(n) \le 2\lfloor \log_2 n\rfloor + 2\) (the upper bound is proved in problem C2.1). Hence \(M(n) \in \Theta(\log n)\).

5. A warning example: naive Fibonacci

Fibonacci numbers: \(F(0) = 0\), \(F(1) = 1\), \(F(n) = F(n-1) + F(n-2)\). The sequence is 0, 1, 1, 2, 3, 5, 8, 13, 21, … The definition translates directly into a recursive algorithm:

ALGORITHM F(n)
//Computes the nth Fibonacci number recursively by using its definition
if n ≤ 1 return n
else return F(n − 1) + F(n − 2)

Basic operation: addition. Each call with \(n > 1\) makes two recursive calls and one addition: \[ A(n) = A(n-1) + A(n-2) + 1 \quad \text{for } n > 1, \qquad A(0) = 0,\; A(1) = 0. \]

Solving. Backward substitution does not work well with two terms. Instead, add 1 to both sides and let \(B(n) = A(n) + 1\): \[ B(n) = B(n-1) + B(n-2), \qquad B(0) = 1,\; B(1) = 1. \] This is the Fibonacci recurrence shifted by one position, so \(B(n) = F(n+1)\) and

\[ \boxed{A(n) = F(n+1) - 1 \in \Theta(\varphi^n)}, \qquad \varphi = \frac{1 + \sqrt5}{2} \approx 1.618, \]

because \(F(n) = \frac{1}{\sqrt5}(\varphi^n - \hat\varphi^{\,n})\) with \(|\hat\varphi| < 1\), i.e. \(F(n) \approx \varphi^n / \sqrt5\).

Why is it so slow?

The algorithm solves the same subproblems again and again. The tree is "almost" a full binary tree of height \(n\), so it has an exponential number of nodes. For \(n = 40\) it makes \(F(41) - 1 = 165\,580\,140\) additions to compute a number that a loop finds with 39 additions.

Fix 1: memoization

Memoization means storing the result of each subproblem the first time it is computed, and reusing it later.

ALGORITHM MemoF(n)
//Global array memo[0..n] initialized with −1
if n ≤ 1 return n
if memo[n] = −1
    memo[n] ← MemoF(n − 1) + MemoF(n − 2)
return memo[n]

Each value \(F(2), \dots, F(n)\) is computed once, with one addition: \(A(n) = n - 1 \in \Theta(n)\). Extra memory: the array and the stack, \(\Theta(n)\).

Fix 2: iteration

ALGORITHM Fib(n)
//Computes the nth Fibonacci number iteratively
F[0] ← 0;  F[1] ← 1
for i ← 2 to n do
    F[i] ← F[i − 1] + F[i − 2]
return F[n]

Additions: \(\sum_{i=2}^{n} 1 = n - 1 \in \Theta(n)\). Keeping only the last two values reduces the memory to \(\Theta(1)\).

6. Recursion vs. iteration

Stack depth is memory

Each active call keeps a stack frame (its parameters, local variables and return address) until it finishes. The maximum number of frames at the same time is the recursion depth, and the extra memory of a recursive algorithm is proportional to it.

AlgorithmBasic operationsRecursion depth (memory)Iterative version: memory
Factorial \(F(n)\)\(n\)\(n + 1\) — \(\Theta(n)\)\(\Theta(1)\)

Hanoi\(2^n - 1\)\(n\) — \(\Theta(n)\)—

Naive Fibonacci\(F(n+1) - 1\)\(n\) — \(\Theta(n)\)\(\Theta(1)\)
Note

The time of naive Fibonacci is exponential, but its memory is only linear: the stack holds just one path from the root to a leaf of the tree at a time. Time is the number of nodes of the recursion tree; memory is its height.

In Python the default recursion limit is about 1000 frames: RecMax on a list of 5000 elements raises RecursionError, while the loop version works for any size.

Tail recursion

Definition

A recursive call is a tail call if it is the last action of the function: its result is returned directly, with nothing left to compute afterwards. A function whose recursive calls are all tail calls is tail-recursive.

The factorial \(F(n) = F(n-1) * n\) is not tail-recursive: after \(F(n-1)\) returns, a multiplication still has to be done, so the frame must be kept. We can make it tail-recursive with an accumulator:

ALGORITHM FactAcc(n, acc)
//Computes n! ∗ acc; call as FactAcc(n, 1)
if n = 0 return acc
else return FactAcc(n − 1, acc ∗ n)

A tail-recursive function can be mechanically turned into a loop: "replace the parameters and jump to the start". Many compilers (Scheme, Haskell, often C with optimization) do this automatically, so the stack depth becomes \(\Theta(1)\). Python does not, so in Python prefer an explicit loop:

def fact_loop(n):
    acc = 1
    while n > 0:          # FactAcc(n, acc) → FactAcc(n - 1, acc * n)
        acc, n = acc * n, n - 1
    return acc

The number of multiplications is still \(n\); only the memory changes.

7. Summary and formula cheat sheet

Summary
  • Plan: size → basic operation → cases? → recurrence + initial condition → solve.
  • Recurrence = (sum of the counts of the recursive calls) + (operations done by the call itself). The base case gives the initial condition.
  • Backward substitution: substitute, find the pattern after \(i\) steps, choose \(i\) to reach the initial condition, verify by induction.
  • For \(\lfloor n/2 \rfloor\) recurrences, solve for \(n = 2^k\); the smoothness rule extends the order of growth to all \(n\).
  • Recursion tree: time = number of nodes (× work per node); memory = height of the tree.
  • Repeated subproblems (naive Fibonacci) cause exponential time. Fix: memoization or iteration.
