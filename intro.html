Introduction: what we measure and how we compare

Before analyzing algorithms we need four ideas: input size, basic operation, order of growth, and the three cases (worst, best, average). This page is a short review. If you already know it, jump to the entry quiz.

After this introduction you will be able to
  • choose a sensible input size and basic operation for a simple algorithm;
  • read and use the notations \(O\), \(\Omega\), \(\Theta\);
  • explain the difference between the worst, best and average case.

1. Input size

An algorithm runs longer on bigger inputs. So we describe its efficiency as a function of the input size, usually written \(n\).

Definition — input size

The input size is a number that measures "how big" the input is. Common choices:

  • an array or list: the number of elements \(n\);
  • an \(n \times n\) matrix: the order \(n\) (sometimes the total number of entries \(n^2\));
  • a single number \(n\) (for example in primality testing): the number of bits \(b = \lfloor \log_2 n \rfloor + 1\).
Watch out

For algorithms that take a single number, the value \(n\) and the size \(b\) are very different. A loop that runs \(n\) times looks "linear", but in terms of the size it runs about \(2^b\) times — exponential.

2. Basic operation

Measuring time in seconds depends on the computer. Instead we count how many times the algorithm performs its most important operation.

Definition — basic operation

The basic operation is the operation that contributes the most to the total running time. Usually it is the most time-consuming operation in the innermost loop. We write \(C(n)\) for the number of times it is executed on an input of size \(n\).

Then the running time is approximately \(T(n) \approx c_{op} \cdot C(n)\), where \(c_{op}\) is the time of one basic operation on a particular computer. The constant \(c_{op}\) does not change the order of growth, which is why we can ignore it.

A useful fact: if you double \(n\), then \(n^2\) grows 4 times, \(n^3\) grows 8 times, \(\log_2 n\) grows only by 1, and \(2^n\) is squared.

4. The notations O, Ω, Θ

These notations compare the growth of a function \(t(n)\) (usually our count \(C(n)\)) with a simple function \(g(n)\) such as \(n^2\).

Definitions
  • \(t(n) \in O(g(n))\) — "\(t\) grows no faster than \(g\)": there exist a constant \(c > 0\) and an integer \(n_0 \ge 0\) such that \(t(n) \le c\,g(n)\) for all \(n \ge n_0\).
  • \(t(n) \in \Omega(g(n))\) — "\(t\) grows no slower than \(g\)": \(t(n) \ge c\,g(n)\) for all \(n \ge n_0\).
  • \(t(n) \in \Theta(g(n))\) — "\(t\) grows at the same rate as \(g\)": \(c_2\,g(n) \le t(n) \le c_1\,g(n)\) for all \(n \ge n_0\).

Example. \(\tfrac{1}{2}n(n-1) \in \Theta(n^2)\). Indeed, \(\tfrac12 n(n-1) = \tfrac12 n^2 - \tfrac12 n \le \tfrac12 n^2\) for all \(n \ge 0\), and \(\tfrac12 n^2 - \tfrac12 n \ge \tfrac14 n^2\) for all \(n \ge 2\).

Shortcut with limits. To compare \(t(n)\) and \(g(n)\), compute \(\displaystyle \lim_{n\to\infty} \frac{t(n)}{g(n)}\):

  • \(0\) — \(t\) grows slower: \(t \in O(g)\) but not \(\Theta(g)\);
  • a constant \(c > 0\) — same order: \(t \in \Theta(g)\);
  • \(\infty\) — \(t\) grows faster: \(t \in \Omega(g)\) but not \(\Theta(g)\).
Rule of thumb

For a polynomial, keep only the leading term and drop its coefficient: \(3n^3 + 100n^2 + 7 \in \Theta(n^3)\). The base of a logarithm does not matter: \(\log_3 n = \log_2 n / \log_2 3\), so \(\log_3 n \in \Theta(\log_2 n)\).

5. Worst, best and average case

For many algorithms \(C\) depends not only on \(n\) but also on the particular input. Sequential search stops as soon as it finds the key, so it can make 1 comparison or \(n\) comparisons on arrays of the same size.

Definitions
  • Worst case \(C_{worst}(n)\): the maximum number of basic operations over all inputs of size \(n\). It is a guarantee: the algorithm never does more.
  • Best case \(C_{best}(n)\): the minimum over all inputs of size \(n\).
  • Average case \(C_{avg}(n)\): the expected number of basic operations on a "random" input of size \(n\). It requires an assumption about how inputs are distributed (probabilities).

For sequential search in an array of \(n\) elements: \(C_{best}(n) = 1\) (the key is the first element), \(C_{worst}(n) = n\) (the key is last or absent). The average case is computed in Module 1.

Common confusion

"Best case" means the best input of a fixed size \(n\), not a small \(n\). Saying "the best case is \(n = 1\)" is wrong.
